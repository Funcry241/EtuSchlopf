## Governance classification

Take-Change-Control classifies the added control-flow predicate as selector-sensitive implementation code. Therefore this implementation contract intentionally declares `SelectorChange: yes` and `SelectorRole: repair_scope` even though r1124 does not introduce a new musical target selector. The frozen parent error class remains byte-identical; r1124 only narrows proof transport to the already authorized safety scope.

## Causal boundary

The comparison is replacement-to-replacement. `raw_forward_nodes_planned` is the concrete replacement count produced by the existing plan, while `canonical_shadow_conflict_suppressions` is incremented only after the corresponding singleton materialization has positively reproduced the bound canonical shadow-rest conflict. Candidate-lane cardinality is not used as a substitute.

## Authority boundary

`ExactCandidateDelta=ja` in this branch means only `fully explained authority withholding`. `candidate_accepted` remains false, `forward_nodes_accepted` remains zero, the source XML is returned byte-identically, and no commit/write authority is created. Partial suppression, absent bound proof, parse failure, backup/forward failure, an independent cross-staff suppression, or any surviving replacement retains the previous fail-closed behavior.

## Multiplicity boundary

Independent duplication cannot broaden write authority. Each duplicate concrete replacement must independently satisfy the same frozen conflict predicate; otherwise equality with the positively suppressed replacement count fails and the exact proof is withheld.

## Scope limit

r1124 changes neither the canonical shadow-rest error class nor the r1121 materialization veto nor the r1122 manifest consumer. It transports the already existing positive proof across one early-return control-flow boundary.
