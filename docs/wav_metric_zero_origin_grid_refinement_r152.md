## Why r152 exists

The r151 full-corpus run separated oracle-discoverability from audio-side identifiability.

The corpus showed:

- the coarse 129.326 BPM family is WAV-only TempoFamilyRank 1 for Etudes 1-9;
- Etude 10 is the only exception, where 211.005 BPM leads 129.326 BPM by only 522 vs. 520 raw tempo votes;
- the oracle-compatible family remains globally span-coherent;
- absolute origin expansion and phase aliases remain ambiguous if the audio rank is based only on coarse tempo votes and narrow modulo-phase bins.

The same corpus also qualified a much stronger Phase-A source contract. With the r151 coarse quarter near 20,460 frames, the observed silent prefixes are not arbitrary:

- Etude 2: frame 0;
- Etude 1: frame 5,088, approximately one sixteenth;
- Etudes 3, 4, 6, 7, 8, 9, 10: frame 20,354/20,355, approximately one quarter;
- Etude 5: frame 40,709, approximately two quarters.

These values line up even more closely with about 20,354 frames per quarter, i.e. approximately 130 BPM. This is evidence that the current WAV corpus is exported on the same project timeline and that **physical WAV frame 0 is project-time origin**. First audible activity may occur later because the musical source itself begins with rests.

This is exactly the conditional contract anticipated by Take 1: when the real corpus proves reliable project-time-zero export, Phase A may bind that input convention explicitly instead of inventing a padding detector.

## Important scope of the zero-origin contract

`OriginFrame = 0` is a **LegacySourceParityPolicy for the current Phase-A corpus**.

It is not claimed as a universal law of arbitrary audio recordings.

It does not mean:

```text
first non-zero frame = measure 1 beat 1
```

Instead:

```text
physical WAV frame 0 = project metric time 0
```

and initial acoustic silence remains a legitimate musical/project-time interval.

The existing Phase-A source contract remains 4/4 with 96 ticks per quarter. More general meter/origin inference remains future capability and is not smuggled into this take.

## Audio-only grid refinement

r151's tempo histogram uses bins of `2 * HopFrames`. At 44.1 kHz this is 440 frames, so the coarse family center 20,460 frames corresponds to 129.326 BPM even when the real grid lies closer to 20,354 frames.

r152 keeps the coarse histogram as the discovery layer, then refines each coarse tempo family **before the FLP oracle is loaded**.

For every coarse family, candidate quarter lengths within plus/minus one coarse tempo bin are evaluated against the WAV-only pulse attacks on a sixteenth grid anchored at frame 0.

The grid distance is scale-normalized. A faster grid does not win merely because it contains more grid lines.

For each family r152 records:

- coarse tempo-family rank;
- coarse quarter frames;
- refined quarter frames;
- refined BPM;
- raw tempo votes;
- all-attack normalized grid alignment;
- dual energy+transient normalized grid alignment;
- median normalized grid residual;
- first-nonzero frame and its residual to the refined grid.

No FLP information participates in any of these values or ranks.

## Scale-neutral ranking

For a pulse attack at frame `f` and candidate quarter length `q`, r152 measures the distance to the nearest rational sixteenth grid point generated by:

```text
4 * f ~= k * q
```

Residuals are normalized by the half-sixteenth width. Therefore unrelated fast-tempo aliases do not receive an automatic advantage from denser grid spacing.

Within a coarse family, the quarter length is selected by:

1. higher all-attack normalized grid alignment;
2. higher dual-family grid alignment;
3. lower median normalized grid residual;
4. smaller movement from the coarse family center.

Across tempo families, the same audio-only grid evidence ranks families first; raw tempo votes are only a later tie-breaker.

This is intentionally qualitative/lexicographic evidence ordering, not a universal scalar confidence.

## Hard anti-leakage boundary

The execution order is now:

```text
WAV
 ↓
attack / pulse evidence
 ↓
coarse tempo families
 ↓
zero-origin sixteenth-grid refinement
 ↓
audio-only grid-family ranking
 ↓
top grid hypotheses frozen
 ==============================
 evaluation boundary
 ==============================
FrozenLegacySourceOracle
```

The FLP oracle cannot:

- generate a coarse tempo family;
- choose a refined quarter length;
- change the grid rank;
- choose an origin;
- reorder the top grid candidates.

## Audio-identifiability evaluation

After the audio candidates are frozen, r152 evaluates the already-ranked `AudioZeroOriginGrid#1..3` against the legacy oracle.

Unlike the r151 `Evaluation#` list, this list is **not oracle-sorted**.

`AudioIdentifiabilityEvaluation#1` always means:

> the candidate WAV itself ranked first.

The new diagnostic gate:

```text
WAV METRIC AUDIO-IDENTIFIABILITY READY
```

is true only if that WAV-ranked first candidate, with `OriginFrame = 0`, satisfies the unchanged r151 oracle-compatibility contract:

- span ratio 80%-125%;
- Match40 >= 75%;
- Match80 >= 90%;
- median residual <= 25 ms;
- P90 residual <= 80 ms;
- at least 8 unique legacy onsets.

The oracle therefore only verifies the already-made audio choice; it cannot rescue a lower-ranked candidate.

## Tests

r152 adds synthetic audit tests proving that:

1. zero-origin refinement can recover an exact quarter period hidden inside a coarse tempo bin;
2. grid coherence can rank the correct family above a nearby raw-vote alias even when the alias has slightly more raw votes;
3. the frozen audio-identifiability hypothesis keeps project origin fixed at frame 0.

## Explicit non-changes

r152 does not change:

- productive FLP source authority;
- `CanonicalSourceEvents`;
- pitch reconstruction;
- staff/hand/voice logic;
- existing WAV articulation;
- phrase evidence or slur materialization;
- writer roots;
- master or render MusicXML behavior;
- PDF policy;
- dependencies;
- network behavior.

No model, MIDI authority or source cutover is introduced.
