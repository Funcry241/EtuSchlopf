# Sicherheit

EtuSchlopf ist experimentell und wird privat gepflegt. Es gibt keine garantierten
Antwortzeiten, Sicherheitskorrekturen oder Unterstützung älterer Versionen.
Eine Sicherheitsmeldung kann sich auf jeden Stand beziehen; daraus folgt keine
Wartungszusage. Nenne möglichst Version, Revision und gegebenenfalls Git-Commit.

## Eine mögliche Sicherheitslücke melden

Nutze auf GitHub die
[Security-Advisories-Seite des Repositorys](https://github.com/Funcry241/EtuSchlopf/security/advisories).
Wenn dort „Report a vulnerability“ angeboten wird, verwende diesen privaten
Meldeweg. Seine Aktivierung ist eine eigene Repository-Einstellung und wird
durch diese Datei weder hergestellt noch zugesagt.

Falls der private Meldeweg nicht angeboten wird, eröffne ein neutrales
[Issue](https://github.com/Funcry241/EtuSchlopf/issues/new) mit der Bitte, einen
privaten Sicherheitskontakt über GitHub bereitzustellen. Veröffentliche dort
keine Details zur Lücke, keine Exploits und keine betroffenen privaten Daten.
Warte auf einen vereinbarten vertraulichen Weg, bevor du diese Angaben teilst.
Ein öffentliches Issue ist kein vertraulicher Kanal.

Eine vertrauliche Meldung sollte betroffenen Stand, Voraussetzungen, Schritte
zur Reproduktion und mögliche Auswirkungen enthalten. Verwende nur die Daten,
die zum Nachvollziehen nötig sind. Bitte vereinbare eine Veröffentlichung der
Details mit dem Inhaber, soweit eine Abstimmung möglich ist.

## Umfang

Diese Richtlinie betrifft mögliche Sicherheitslücken des Projekts, zum Beispiel
beim Umgang mit Eingabedateien, Dateipfaden, lokalen Diensten oder externen
Prozessen. Gewöhnliche Programmfehler und Notationswünsche gehören in die Issues.
Verhaltensbeschwerden sind im [Verhaltenskodex](CODE_OF_CONDUCT.md) beschrieben.

Die Watch-Oberfläche ist als lokale Laufansicht vorgesehen. Die Existenz einer
lokalen Oberfläche ist keine Zusicherung für einen sicheren Internetbetrieb.
Eine abgeschlossene unabhängige Sicherheitsprüfung wird hier nicht behauptet.
