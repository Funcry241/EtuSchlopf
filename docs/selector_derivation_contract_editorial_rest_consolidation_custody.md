## Scope and unchanged musical authority

RefactorOnly on accepted r1417. This closes the unsupported N:1 received-origin
transport shape at the actual existing editorial rewrite emitter. The existing
musical selector, capability, exact edit script, output bytes, receipt mint and
adoption rules remain unchanged. Failure to capture observation never changes
that accepted edit or adds a release veto. Failure to prove continuation remains
Unknown in the existing selected-custody observer.

The new opaque rest creation is minted only under the existing sealed editorial
owner capability. The journal binds actual input/output byte ranges to one exact
execution and requires that receipt's original owner and opaque event identity.
A different receipt cannot replay a creation even when its input/output bytes
are identical. Those ranges locate already
received identities in one bound epoch; they never mint or infer a source, course,
role or origin from output geometry. An N:1 root keeps every parent's creation,
root and received support as separate ancestry edges. It has no invented singular
SourceEventId. Every original root's full support remains independently checked.
Nested consolidations retain intermediate roots as well as all original ones.

An interval hull does not prove coverage: gaps, extensions, nonpositive support,
foreign executions, missing/duplicate parents, reused creation identities,
ambiguous outputs and staff changes refuse continuation. A parent already
transported by the existing explicit relocation keeps its original obligation
span; overlap with a consolidated output is mapped back through that original
edge. No general disappearance, hand transfer or N:0 omission is introduced.

Common received course context is retained only when every authenticated parent
already carries the same positive course and generator presentation. Mixed or
missing context stays Unknown. This is not a newly declared musical course and
never substitutes for the independently required canonical role. Visible rest
responsibility, negative-rest context and canonical role decisions remain governed
by the unchanged canonical_rest_context_v1 and role_occurrence_binding_v1 contracts.
All role-sensitive readers, groupings, channel edges and labels remain untouched.

## Evidence and limits

Fresh accepted r1417 evaluation identifies the editorial replacement boundary as
the first selected-custody failure in eight of ten projects. That observation
motivates evaluation only; neither those projects nor any location defines this
scope. The receipt captured the actual edit, but the received-context continuation
had no representation for its N:1 parents. Whether each real rewrite meets the
strict support/staff/context proof must be measured on a fresh Windows run.
This Take does not promise that all eight become complete: missing independent
course/role context or another unsupported later owner must remain visible.

Normative tests use synthetic generator/arrangement custody and the actual
editorial owner, exact receipts and continuation. They cover both staff
presentations, distinct opaque sources, nested consolidation, independent measure
duplication, label renaming, missing capture, foreign execution, forged/missing/
duplicate/cyclic ancestry, incomplete support, mixed staff, independent course
origins, and gap/overlap/endpoint geometry under uniform unit scaling. They do
not import real corpus material or retain real measure/identity witnesses.
Existing custody, birth, relocation, receipt/adoption and rest/beam tests remain
mandatory, as do parent-compiled early and packaged admission, all-target tests,
all-target strict Clippy and all-bin build with exact Rust line balance.

The current native losses remain open (previous evaluation: 5/9/1 in projects
6/7/10). This is a necessary ancestry correction, not complete canonical rest-role
closure, a bounded channel assignment or a musical completion claim. The public
one-command workflow remains ./run.cmd --take --all, without force.
