# r1475: closed immutable voice-plan input admission for E050

Parent: r1474. Class: KodexOnly. No musical or runtime pipeline change.
This preparation is conditional on native acceptance of r1474.

## Why this additional governance step exists

The r1474 causal contract requires an actual canonical binding before a bridge
may consult the sealed voice plan. E050 currently receives only XML, a report
label and a path. Passing the additional read-only context in the first repair
draft was rejected by the architecture build gate's population freeze. The four
parent take checks alone had not reached this compile-time signature check.
No rejected draft is a delivered or accepted repair.

The installed gate already has a closed input migration for original respelling
owner #60. This take follows its strict signature-admission pattern for one
additional existing owner; it does not alter the general receipt-only migration.

## Exact admitted interface change

Only exclusion E050, its exact frozen owner path and original signature, and its
unchanged PRESERVING classification may use the additional signature. The original
XML, label and path inputs retain their names, order and types. Exactly one last
parameter is added:

`voice_guard: &structural_write_authority::CanonicalFinalChordStructuralPlan`

The return remains the existing audit/post pair plus exactly one optional
`PreservingTransformationReceipt`. Mutable, owned, erased, differently named,
additional or generic context inputs are rejected, as are another owner,
classification, original signature, missing receipt or changed receipt kind.
Multiple definitions do not qualify. The gate is still active and fail-closed.

This is an explicit, bounded expansion of interface admission. It does not prove
the future binding implementation safe and does not itself create a guard,
source identity, voice plan, new transformation, sink, receipt capability or
permission to edit voice labels. Population/exclusion tables, E050's beam-only
purpose, the preserving verifier and mint ownership remain unchanged.

The existing exact trust-anchor hash for this gate is updated to its new bytes.
No other trust pin or validation condition is removed or generalized.

## Scope of a later repair

The accepted-parent causal definition and evidence requirements from r1474 remain
unchanged. The first repair will consult the already sealed plan at E050's actual
input and withhold groups that cannot stay in one lane. Whole attached chord
resources, exact-input binding, stale/unbound negatives and independent duplication
must be covered. Construction belongs in the existing canonical structure module;
XML labels, paths or global state must not fabricate a plan or binding.

The early-to-late extension transport required for E6/T32 remains deferred. The
interface admission does not authorize treating the frozen plan as the final
alignment plan, nor reconstructing an extension from final XML. No music-effect
approval is asserted by this governance take.
