# r1164 — ReanchorRestVisibilityScopeWitnessProjection

Parent: accepted v0.10.1839 r1162 `FinalChordVisibleRestIntervalEpochWitnessAuditWarningDebtClosure`.
ChangeClass: `RefactorOnly`.

## Purpose

r1162 established real pre-FinalChord visible-rest carriers whose final Master representation matches the interval split `R∩N -> Forward` and `R\\N -> visible rest`, while the final Render represents the whole source carrier `R` as Forward in several projects. The r1162 report deliberately left the Render pre-FinalChord input unavailable and therefore did not identify the Render writer that produced the whole-R Forward.

The already productive `ReanchorRestVisibilitySafetyNet` trial has diagnostic outcome data in `InitialRenderTransaction`, including whether it wrote and the measure scope/rest-fragment count of every adopted action. That evidence already exists but was discarded before final report projection.

r1164 transports only that pre-existing diagnostic evidence to the existing FinalChord visible-rest epoch-witness report section and adds the dynamic measure identity of each existing epoch witness. No selection predicate, replacement range, writer call, mutation, authority, release rule or artifact source is changed.

## Projection

For every project result the existing section additionally reports:

- `Measure` on each existing `Witness#` row;
- whether the reanchor trial was attempted/written;
- candidate/adoption counts;
- affected measure/rest totals;
- one `ReanchorAction#` row per already-recorded action containing its runtime measure scope, old rest-fragment count and existing risk label.

This take intentionally does **not** add new action-footprint fields. A same-measure correlation is only a scope witness. It does not yet prove that the epoch-witness rest carrier itself was one of the replaced fragments. If the targeted run correlates, a later narrow evidence take may expose the already-selected action intervals without changing the selector.

## Authority boundary

- no MusicXML, Render-MusicXML or PDF mutation change;
- no FinalChord projection change;
- no Reanchor selector or writer change;
- no new semantic proof or repair authority;
- no release veto;
- no project/take/measure constant in executable selection logic;
- runtime measure numbers are report-only evaluation evidence;
- no full-corpus run required for this projection take.
