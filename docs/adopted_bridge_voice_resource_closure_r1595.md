# r1595: Adopted bridge voice resource closure

This MusicMutation refines the existing original-beam voice alignment owner.
The accepted parent is r1594 r02, v0.10.1839. The accepted error classes and
new selector derivation scope are recorded in
selector_derivation_contract_adopted_bridge_voice_resource_closure.md.

## Cause and change

An actual E050 connection can extend an original beam component. The later
canonical voice projection may separate the extension and its tied continuation
from that component; the existing withdrawal then correctly removes the bridge.
Aligning only original members cannot repair this resource split.

The alignment owner now consumes live adopted connection custody and independently
bound pre-lane notation voices. Eligible connection resources join the existing
atomic source/chord closure. Every head must have the component's semantic voice,
all resources must remain in its measure and staff, source roles must be compatible,
and the ordinary occupancy, import and canonical allocation checks still apply.
Conflicting shared-resource proposals are all refused. Original memberships,
positive origin evidence, E050 beam-only authority and withdrawal policy remain.

A private proof binds the exact adopted connection and source identity. Rebinding
and the typed scalar transport reject missing or stale custody. Only proved
connections can transport their technical labels; the existing nonvoice, actual
attachment and single-label checks remain mandatory. Unrelated connections use
the previous transport policy.

## Validation and limits

Synthetic cases exercise the actual original owner, E050 adoption, projection,
alignment, withdrawal and typed transport, including tied continuation. Existing
shift-invariant variants relocate, relabel and duplicate the cases. Negative
checks cover absent custody, changed semantic voice, incomplete resources, stale
proofs and repeated alignment. No corpus coordinates select runtime behavior.

The native r1594 readback motivated the investigation: Etuede 6 T34 lower staff
loses its already adopted bridge after final technical voice projection. T32 is
another possible member of this general class; historical screenshots are not
selectors. The new candidate still needs a native all-etude run and visual review.
Check musical note/rest/tie preservation and existing bridge cases, not only T34.
