## Report-only scope

RefactorOnly: this take explicitly introduces a read-only observation transport
at the existing mixed-source owner boundary. It is not classified AuditOnly:
that class cannot add a data edge in mixed productive source. No path role,
gate, writer authority or decision capability is changed to admit this work.
The actual counterfactual computation remains in PathRole::Audit.

At the existing record_joint_search_result observation, the C3 owner
passes its already observed immutable public kernel domain, selected outcome,
bound source bytes and diagnostic anchor coordinates to c3_diagnostics. No
private field is made public, no original identity is inferred, and no new
getter, writer, receipt, origin, selection callback or feedback path is added.

The observer enumerates every maximal selected combined-state run and its next
return to the same state. It replaces only the intervening excursion in a copy
of the selected path, retaining the entire preceding and following path. No
piece or measure window defines an alternative; every returning excursion is
reported without a global winner. Nonreturning courses yield an explicit zero
count. Hidden heads and other group obligations remain in the original domain.

The unchanged public evaluate_course kernel checks the whole path, including
allowed states, incoming group/capability edges, head protection, exact section
ages and entry/exit context. An invalid alternative is graph-rejected, not given
invented costs. A valid alternative reports its full C3 vector, first differing
primary component and exact ledger metrics. Equal primary costs do not claim a
tie-break result. A better counterfactual is a diagnostic counterexample, not
an adoption or a new ranking decision.

The source SHA-256 and original anchors bind observations to planning point P.
A complete KernelDomain/SelectedPath/Anchors snapshot is recorded as well, so
later explicit user counterfactuals can be evaluated externally on the same
graph without embedding their addresses into program or normative tests. The
SnapshotSchema=1 Debug grammar is tied to the exact accepted source snapshot;
it is diagnostic evidence, not a stable public serialization or new authority.
Anchor labels are output only. Master and Render are observed independently.
The later clef/octave script preparers and writer transactions are not executed
for these alternatives. Graph admission is therefore not a claim of complete
materializability; graph rejection is not reclassified as a writer failure.
If the unchanged primary comparison already disfavors a graph-admissible path,
that ranking explains why it cannot replace the selected course regardless of
any still-unproved later materialization details.

All results go only through the existing diagnostic report collector. No caller
consumes them for music, release, C3 selection or source mutation. Existing
solver states, budgets, priorities, materializers, receipts and gates remain
byte-identical. The restored mathematics bibliography is carried forward as a
documentation correction; it supplies no runtime permission.

## Validation and native boundary

Synthetic tests cover a feasible three-ledger alternative losing to two sign
changes, protected four-ledger heads, fixed-state refusals, complete incoming
and outgoing context, all independent returning excursions, a relocated neutral
prefix and explicit nonreturning input. They contain no corpus fixture or fixed
real-world measure address.

Native acceptance remains pending. All twenty Master/Render XML files must be
byte-identical to accepted r1685; the full-corpus PDFs must remain pixel-identical
under the same raster comparison. Report changes alone do not prove those
invariants. No musical improvement is claimed by this diagnostic take.
