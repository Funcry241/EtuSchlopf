## Observational boundary

The selector-sensitive source classification is handled conservatively by this
implementation contract. The new status classification is used only for report
projection. It is never an input to search, ranking, scope, rejection, writer
permission, adoption or final musical validation. No threshold, weight,
capability or incumbent-retention rule changes.

The comparison basis is the source at planning point P, not r1564's final XML.
An adopted compatible domain can include an unchanged incumbent subcourse;
adopted means joint binding, not necessarily a changed final document.

The collector resets with the existing project course reset. It observes
entry failures before preparation, independent Master and Render results for
each observed system, both cost vectors and strict-improvement flags,
shared-octave compatibility, the last entered failing phase and exact error,
and the adopted/retained completion. Search results are recorded immediately
so a later failure in the other document cannot erase them. Errors in actual
productive adoption remain fatal under the unchanged contracts; this observer
does not fabricate a successful result report on a fatal run.

The report uses the existing register_planner_input owned section through its
existing final-report projection. Batch stdout forwarding is not authority for
this evidence and is not changed. No original source or attack ID is inferred.

## Validation

Normative collector tests are synthetic and independent of corpus identity.
Local paired native fixtures must preserve Master and Render XML byte for byte
against r1564 while retaining C3Diagnostic rows in result.txt. Final native
acceptance requires all twenty corpus XML files to remain byte equal to r1564.
Neither green tests nor source acceptance substitutes for that corpus check.
