## Independent class meaning

A document's horizontal system partition and its vertical page partition are
separate consumer obligations. Under a profile that constructs each horizontal
system before deciding which page receives it, insufficient vertical space can
move the finished system to another page; it cannot explain an additional
boundary inside that system. Such an internal boundary is a counterexample to
the submitted system interval even if page insertions occur as well.

This definition does not infer page independence from a repeated corpus address,
a page count, an empty collapsed set alone or an assumed uniform capacity. It
requires an independently established consumer dependency boundary and complete
binding of horizontal effective inputs. Page placement is irrelevant only to the
extent that this boundary proves it cannot alter those inputs. A renderer whose
usable horizontal width, indent, context or spacing changes with page placement
is not covered by that independence claim without separate binding/proof.

For the independently inspected MuseScore Studio v4.7.4 profile, source tag
v4.7.4 (revision 7688c005ad96), ScorePageViewLayout::doLayout invokes
SystemLayout::collectSystem before page collection. PageLayout::collectPage
collects a finished next system before deciding whether it fits vertically.
SystemLayout::collectSystem compares horizontal width with the configured
pagePrintableWidth. Section/first-system state, system headers/trailers,
following-measure courtesies, frames, noBreak and locks remain actual horizontal
dependencies; they are not discarded merely because page placement is separate.
Fresh CLI import/export and stable consumer/style assets are prerequisites of
that inspected profile. This is not a claim about an incrementally reused GUI
layout or every renderer/version and configuration.

Synthetic external controls demonstrate equal internal horizontal subdivisions
with two different vertical placements of the same submitted interval, including
one genuine unplanned page insertion. Native measure positions provide the
geometry independently of PDF text bands. Such controls support the inspected
dependency argument; finite examples alone do not prove universal independence.
Their concrete dimensions and addresses remain external evaluation evidence and
are not features, thresholds or fixtures of this class.

## Distinctions from existing definitions

renderer_page_partition_nonrealization remains byte-unchanged. A failed complete
page/system plan alone still proves only that complete plan's failure. This
independent class supplies the additional horizontal dependency obligation; it
does not derive a range-level prohibition from the page insertion itself.

A pure page insertion with no internal system subdivision supplies no horizontal
counterexample. Collapsed system boundaries, incomplete readback, failed import,
missing output, ambiguous interval binding or unknown horizontal dependencies
remain unsupported evidence. In particular, the absence of system collapse does
not by itself validate arbitrary page drift or extend an existing repair scope.

## Necessity and invariance

The immutable source and horizontal effective-input binding identify what failed.
The complete submitted partition and supported readback identify an internal
subdivision rather than an unrelated or moved boundary. The consumer dependency
argument distinguishes a horizontal failure from a vertical packing observation.
Without any of these obligations, page-independent range reuse is unproved.

Renaming project/measure/voice identifiers, relocating a fully bound synthetic
example and uniformly scaling its metric time preserve membership when its
horizontal effective inputs are preserved. Independent documents do not share
negative evidence. Duplicating an independent failed interval cannot suppress
another interval's observation or create a global first/unique-winner selector.
Intervals sharing horizontal context must retain that context as a dependency;
they are not declared independent merely by having different addresses.

## Authority boundary for a later repair

This take changes no Rust, classifier, selector, writer, renderer command,
layout choice, preference, capacity, page-count frontier, search budget,
materialization, receipt, channel/role assignment, musical event, SSC or release.
No existing error-class definition or existing pure-system repair is changed.

A later implementation must reference this unchanged definition from an accepted
parent. Its repair scope must separately prove all authority, materialization
and supported-observation boundaries. Only the existing layout owner may consume
an exact interval counterexample. The original complete-plan exclusion and every
independent adoption and musical conservation check remain in force.

Any exclusion remains ephemeral, source-bound, consumer/environment-bound and
horizontal-context-bound. A changed dependency invalidates reuse. No unsupported
page observation grants a system prohibition, copied output boundary, new width
or height model, frontier expansion, force fallback or note removal. Exhaustion
and the existing oracle limit remain honest failures; no convergence guarantee
follows from this definition.

Normative implementation tests must be synthetic and independently derived:
internal subdivision with and without concurrent supported page insertion,
pure-page positive neighbor, collapsed/unknown/foreign-source refusal, context
changes, interval uniqueness, unchanged no-drift choice, independent duplication,
and existing promotion/capacity/frontier guards. Real corpus data remain external
evaluation, never normative fixtures or productive selectors.
