## Resulting behavior

The original register owner keeps its own immutable source input and original
RegisterNotationPlan with retained event identities. Immediately before the
existing octave creator materializes that same input, the owner compares the
incumbent against complete-part alternatives omitting only entire existing lower
register spans. Unavailable contexts retain their complete incumbent. Re-entry
at the register planner starts a fresh epoch and retires old materialization
observations; a previous input cannot supply the new input's proof.

Immutable representation preparation calls the existing octave-direction and
lower-clef measure preparers and exactly the next owner's carried-state measure
traversal. It does not issue origins, adopt bytes, mint a receipt or commit a
file. The existing clef owner computes its complete original solution for those
prepared bytes, with unchanged costs, temporal/chord/tie/beam observations and
following carry. Its normalized script is projected read-only and checked against
exact raw-note conservation, the original tie/beam postconditions, and an equal
objective after projection. A numerical solution without that closure is
unavailable. Only measurements return to the register owner. No private
clef plan or preview XML becomes a productive source.

The combined reader policy is explicit: both the existing scalar cost and the
sum of actual clef transitions and true octave-mapping changes must strictly
fall, with the same visible-object denominator. Continue reminders are reported
separately. There is no new weight, maximum-ledger cutoff or treble/ottava ban.
Alternative complete versions of one part are one conflict group; independent
parts never compete for one scorewide winner. The unchanged incumbent always
remains available and ties preserve it.

Only the selected original semantic proposal is materialized. The original
BLOCK-50 creator, source-bound direction origins, existing lower-clef writer,
clef-course materializers, receipts, adoption and release gates remain in charge.
Raw notes, spelling, sounding pitches, timing, visibility, staff/voice, rests,
chords, beams, ties and slurs receive no mutation permission. The frozen SWA
module, original class definitions, all Kodex gates and cost constants remain
byte-identical to r1547.

## Evaluation and limits

The accepted class is referenced unchanged by the separate repair-scope
contract. Local evaluation is distinct from the normative synthetic test suite.
An isolated replay of the actual original register input for Etude 3 selected
three complete-span omissions. On the same 298 visible lower objects, the old
clef objective decreased from 242 to 190, clef transitions 8 to 4, true octave
mapping changes 12 to 6; maximum ledger count remained 3. This is a same-epoch
planner/materializer experiment, not a final full native corpus run. The earlier
297-object final-document observation belongs to another epoch and is not used
as this decision's input or denominator.

MuseScore 4.7.4 exports byte-identical MIDI from both isolated Etude-3 replays.
The local intermediate score has three pages before the remaining native
notation/layout passes. It is not the final four-page product and does not prove
the final corpus page count. Final native XML/PDF quality, persisted artifacts
and acceptance must be checked in the fresh user run.

The old r1547 same-input observer stays independently read-only and correctly
keeps its own missing early binding UNKNOWN. Its counters are not this new
original-owner decision or authorization. New JointReadingOwner rows report
that decision separately in the original register report.
