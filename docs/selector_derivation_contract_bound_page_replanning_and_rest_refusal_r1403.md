## A. Existing layout owner

Supported evidence has no collapsed page or system boundaries. Inserted pages
still exclude the exact complete partition. An additional internal system
boundary, including concurrent supported page insertion, also excludes its unique
submitted system interval under the independently inspected fresh-import
MuseScore consumer profile in the unchanged horizontal class definition.
Pure page insertion supplies no interval prohibition. The same existing range
owner handles pure and concurrent system subdivisions; no range is copied from
an output into a positive layout directive.

The original committed source is immutable throughout this one invocation.
Each round starts from that source, materializes only the submitted directives,
and verifies both materialization and existing FinalPdfSource preservation.
The existing promoter clones the original plan and varies only page/system
flags; explicit widths must remain equal to the original plan, both when
learning horizontal exclusions and before reusing them. Source contents,
following-measure courtesy context, section/first-system state, frames, locks,
style and spacing are therefore retained rather than inferred from page counts.
In the independently inspected consumer, fresh horizontal formation precedes
vertical placement, uses fixed pagePrintableWidth and cannot split a finished
system for page height. Stable runtime/profile assets remain a prerequisite;
this proof does not extend to arbitrary renderers or mutable GUI state.

The actual consumer/command binding is checked on every subsequent successful
round whenever either kind of exclusion exists, including before confirmation.
Complete submitted starts and readback differences must match exactly; unknown,
foreign, incomplete, collapsed or changed-width observations fail closed.
Intervals with the same source retain their following context. Independent
documents never share exclusions. The joint plan remains one transaction group.

Exclusions are ephemeral and bound to the original immutable source. A typed
actual invocation identity projects the existing validated executable and actual
command directly at the original renderer success return. It is not parsed from
reports and introduces no new raw environment or filesystem identity reader.
The fixed inherited process/profile scope belongs to that single synchronous
oracle instance. No environment values or executable bytes become musical inputs.
A changed successful renderer/command fails closed once a page exclusion exists.
The independently established consumer/readback profile and stable runtime assets
remain prerequisites; this is not a claim to snapshot mutable DLLs/fonts/settings
or detect external modification of an installed renderer during the invocation.
The Debug representation stays opaque. No command form or cache precedence changes.

The planner tracks the rejected complete-prefix equivalence class and per-page
system count during system partitioning, and rejected full-plan prefixes during
page partitioning. Only equivalent states can share a best prefix. Existing
segment, joint-plan and page-count preference comparators retain their authority.
No calibration, added page-count frontier, vertical limit, preference, lookup
identity, search budget or musical role is introduced. With no page exclusions,
the exact old builder is used. With exclusions, all intermediate states are
rebuilt. Exhaustion and the existing eight-round limit remain fatal.

Every promoted plan is checked again against the full exclusions. It receives
fresh native confirmation through the same original shadow materialization,
receipt, immutable-source and productive adoption boundaries. No observation
becomes a copied output boundary or a second writer. Musical conservation,
source/attack identity, temporal proof and SSC remain independent requirements.

## B. Existing StrictStaff owner

The accepted unbound-rest class is unchanged. A physical staff/voice projection
gap is not musical silence authority. At partial cross-staff pitched overlap,
the entire proposed overlay is refused without inventing a label, rest fragment,
role or chord host. Existing cross-staff material is not prohibited or removed.
The original full-pitched-coverage negative guard, normalized metric-rest domain,
legacy action reservation, writer root, exact receipts and adoption stay intact.
Unsupported metric bases remain non-writing. The unrelated positive neighbor and
actual original receipt integration test remain required.
