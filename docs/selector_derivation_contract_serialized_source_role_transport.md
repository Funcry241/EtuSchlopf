## Result and authority

The existing canonical pitched source-role relation, previously retained only in
FrozenSerializationVoiceChannelPlan, is now copied into FrozenSerializedVoicePlan
and every paired label-alpha variant. The primary-beam partition binder reads its
already authenticated SourceEventId directly, after the unchanged exact
source/attack/physical-occurrence checks. The accepted allocator still assigns
one canonical role per channel. Hence the new read equals the previous label-role
read for every complete production input; class eligibility, role derivation,
channels, labels, conflict edges, materialization and receipts do not change.

The label binder requires exact key coverage between source-channel and
source-role relations. Missing or unexpected source-role entries fail closed;
there is no label/channel fallback. The beam binder excludes an affected
candidate with a missing source role under its existing incomplete-binding path.
An authorized beam channel rebind retains the source's original canonical role;
it does not promote the source by moving its label to the primary channel.
The target channel's existing primary-role assertion remains mandatory.

This implements the next dependency cut of the unchanged accepted
role_occurrence_binding_v1 contract and r1346 source-role foundation. It adds no
new error class, musical role inference, occurrence issuer or writer. The
implementation contract records the complete-source-role safety precondition;
it does not narrow the accepted causal beam class to a known witness.
The accepted written/partwide-capacity/headless/staff-projection contracts and
all channel-allocation and SSC/P2/identity-bridge runtime code remain unchanged.
The source-role table is pitched-source evidence, not a complete occurrence-role
plan and never a rest role. Multiple notation fragments are not collapsed into
a newly inferred occurrence identity.

## Why this does not claim a musical repair

Fresh r1416 Windows evidence proves take acceptance, 2157 passing tests in 15
targets, 10/10 projects, Clippy and build success. The separate native MuseScore
4.7.4 evaluation still counts five missing pitched occurrences in project 6,
nine in project 7 and one in project 10. Project 6's four earlier wrong-staff
occurrences are now retained on their required staff; its independently
represented upper material instead exposes two additional slot losses. These
are evaluation observations, never predicates or normative fixtures.

The existing role-sensitive consumers still include visible-shadow-rest scope,
rest-readability grouping and lower primary beat/beam continuity. Existing
non-pitched continuation carries physical identity but no independent canonical
presentation role. Source roles or XML labels cannot fill that gap. The accepted
canonical_rest_context_v1 contract also requires musical-run grouping to become
independent before mixed-role reuse. This Take therefore does not remove any
role-incompatibility edge, admit mixed-role channel sharing, reassign a rest,
change the native command or claim that a bounded assignment has been found.
The separate existing bridge audit's continuation limitation remains open.
