## Behavior and authority

The existing E050 bridge writer previously grouped notes by their current Render
voice. A later projection can apply a sealed voice plan that separates them.
The new read-only guard binds the actual complete input using the existing
canonical structure, source/attack/fragment bindings, render occurrence witnesses
and sealed voice labels. It neither mints source identity nor reads Master files,
report text, filenames or global state to infer identity.

Each existing proposed group is checked with its attached chord resources. A
shared sealed label retains the old hierarchy and E050 write path. Distinct labels
withhold the whole group. An absent, stale or incomplete guard cannot authorize
that group; failure to construct the overall authentic binding aborts the stage
with context rather than guessing. Refusal counters are reported observationally in the console as
`BridgeFrozenVoiceCompatibility`, explicitly before adoption and without granting
write authority.

The exact-input guard is private data carried in a temporary clone of the already
exported canonical structural-plan type. No additional central export, token,
writer, sink, allocation or receipt purpose is added. The stage retains its real
canonical plan unchanged. E050 receives precisely the immutable input admitted
by r1475 and still emits its original PRESERVING receipt; the unchanged adoption
boundary verifies actual candidate bytes. The guard changes only selection of
existing beam writes; it performs no voice write.

This uses the byte-unchanged causal contract and evidence requirements frozen by
r1474. All validators, existing trust pins, owner/exclusion tables and capability
budgets are byte-identical to r1475. Later OriginalBeamVoiceAlignment behavior,
original membership and early-to-late extension transport are unchanged. E6/T32
is not repaired by this take. The frozen plan is not claimed to be the eventual
late alignment plan.

## Concrete evaluation hypothesis and scope expansion

The initial expectation was one location, E6/T34. Read-only inspection of existing
r1473 snapshots found three additional groups with distinct labels after the first
post-bridge FinalNotation projection. Their occurrence shapes remain matched in
that comparison. This is observational scope forecasting, not an authentic runtime
binding proof or a productive selector. No local corpus renderer run was used.

| Project/measure | Group onsets (divisions 96) | First projection labels |
| --- | --- | --- |
| E3/T6 | 192, 216, 264 | 4, 2, 2 |
| E5/T36 | 96, 120, 168 | 4, 2, 2 |
| E5/T37 | 96, 120, 168 | 4, 2, 2 |
| E6/T34 | 96, 120, 168 | 2, 2, 6 |

At all four locations Master has an original two-note begin/end pair followed by
an unbeamed final note. Withholding the extension should restore that beam shape.
Later compensation or renderer-dependent behavior could change the final effect;
only native evaluation can confirm it. No special case was added to retain the
three extra bridges or isolate a known measure. The guard uses neither these
locations nor the number four. They appear only here as review/evaluation targets.

Expected final effect: at each location the pair's second note becomes end and
the extension's last note loses its beam, on levels 1 and 2. This forecasts eight
changed note states per level across four locations, all toward Master. It is not
an assertion that this exact output has already been observed. Other locations,
levels, voices and non-beam content must remain unchanged or acceptance stays open.
