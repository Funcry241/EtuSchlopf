# r1399: SSC failure replay lessons (advisory only)

This document records external evaluation, not a new error class, classifier,
selector, receipt, writer, repair, runtime rule or release authority. It is
metadata in the definition-only Take. Parent is accepted r1397; rejected r1398
never became an accepted foundation.

## Findings and limits

The rejected definition Take executed the parent's identical Rust and failed
during a project run, after build/admission. The actual input/output XML of the
observed owner boundary was recovered from interleaved console hex and verified
against its original lengths and SHA-256. The real notation-polish and layout
owners replayed four times to the exact original output. The original freshly
minted compressed receipts received 128 Permit decisions from the unchanged
SSC classifier and adoption decision. An additional external storage probe
preserved exact bytes in 1024 encode/decode roundtrips over four threads.

The failed canonical witness can be matched exactly by changing a whitespace
newline 0x0A to J 0x4A: one bit, the reported position, excerpt and 31 additional
canonical bytes. This change occurs in neither hash-bound original XML nor the
replayed owner output. A fixed basis:canonical prefix explains 16 reported
witness bytes; that prefix is not corruption.

These measurements locate a discrepancy; they do not identify the component
that caused it. Hardware failure, a platform/library issue or another problem
in that execution remains undecided. Passing Linux replays do not exclude a
Windows- or optimization-dependent defect. A prior pass does not prove that a
later identical-source run will pass. No content fix or definite cause is
claimed. All external real-score inputs and diagnostic helpers stay outside
the managed source tree and normative tests.

## Consumer allocation lesson

Native synthetic neighbors demonstrate that an overlapping consumer channel
can resolve to independent staff tracks and retain a mixed-staff group's bound
staves. This requires partwide allocation evidence: three ordinary channels
plus one overlapping channel retain all ten synthetic notes, while four
ordinary channels plus that channel retain only eight of twelve, both with
converter Exit 0. Synthetic tie, staff-permutation and scale controls retain
six notes and four tie markers. They contain no octave shifts and do not close
the separate octave/tie-boundary obligation.

No existing musical event may be invented, omitted, retimed or moved between
staves to trigger a convenient allocation mode. Raw labels, capacity success,
majority counts and converter success grant no role or chord-split authority.
The complete bound representation must prove capacity, consumer staff retention
and existing musical compatibility together.

## Process consequence

A failed reexec needs its actual phase and original evidence, not an assumed
optimizer cause. Gate/bootstrap optimization, test compilation and productive
program optimization are separate settings. This Take changes none of them.
The local verification uses an explicit productive-package opt-level 1 override.
The shipped strict profile remains the parent's profile; local compiler flags
are not installed as product configuration.

Sovereign adoption, SSC classifications, fatal refusal, transaction rollback
and all frozen containment envelopes remain unchanged. Discarding an optional
variant after a refusal is not automatically authorized by its being optional.
A later implementation needs an independently legitimate owner boundary.

Fresh user acceptance is required. Only an accepted unchanged class definition
can be the foundation for subsequent staff-projection implementation. This
Take does not repair music and does not promise a remaining Take count.
