## New finding

The parent term `Applied` is intentionally local to the structural authority boundary: the replacement bytes were executed in that particular in-memory buffer. It is not a claim that this buffer subsequently won a candidate comparison, replaced the current `best`, crossed a final readback acceptance branch, or became a persisted artifact ancestor.

Therefore `UNKNOWN` cannot be treated as a defect by itself. Before any additional receipt transport is added, r1193 separates candidate/trial application from selected-state application.

## Selection observation

r1193 adds `observe_selected_state(xml)` to AuditOnly.

The observer fingerprints the exact complete document state and reads only receipt provenance that r1192 has already attached to that exact state. It does not search for edits inside the XML and it does not manufacture identity from a physical locator.

The observer is called only after an existing productive owner has already selected or accepted a state. The observation has no return value and cannot influence the decision.

Two already-existing deterministic post-steps sit between an attributed authority result and a later selection handoff: corpus patch Visible-Rhythm normalization and editorial-voice post-integration rest visibility. r1193 observes these only as exact complete-document `before -> after` successors and transports the already-known receipt set conservatively into the successor state. This is not occurrence matching and cannot add a receipt that was absent from the predecessor state.

Covered ownership points for the frozen accepted-r1192 UNKNOWN family are:

1. direct accepted register-notation materialization after the existing validation succeeds;
2. direct lower-staff clef readability materialization after its existing mutation loop;
3. accepted hidden-chord consensus/Gauss/broken/tail candidate after it replaces `best`;
4. every existing corpus repair `best` replacement consuming overfull/atomic move/restify candidate material;
5. accepted cross-staff editorial-voice candidate after the existing decision copies it into `best.layout_xml`;
6. accepted final-rest glyph-height readback candidate after the existing exact-candidate-delta gate succeeds.

These ownership points cover the selector consumers capable of selecting states generated by the ten r1192 UNKNOWN origins. No candidate is made selectable by this take.

## Disposition classes

For every edit already classified `Applied` by r1188/r1192:

`FINAL_RECEIPT`
: The existing r1192 final-epoch ledger has an identity-safe final receipt for the same opaque edit identity.

`SELECTED_NO_FINAL_RECEIPT`
: No final receipt exists, but the same receipt identity is present in an exact complete-document state observed after an existing productive selection/acceptance handoff.

`NO_SELECTION_WITNESS`
: No final receipt exists and the receipt identity was never present in any exact state observed at the covered selection handoffs. No exact selected-state witness exists within this frozen scope; the class does not by itself prove whether the state was rejected, superseded, or lost across an unobserved transport boundary.

The three classes are mutually exclusive and exhaustive over `Applied` identities. `AccountingMismatch` must be zero.

## Conservative equal-state rule

r1192 already intersects receipt provenance when identical complete-document bytes have independent producers. r1193 reuses that conservative state evidence. A selection observation can therefore mark only identities that remain certain for that exact state after the parent ambiguity rule; it cannot pick a producer by order or context.

## Authority boundary

The disposition is historical process accounting only. It proves neither musical correctness nor semantic necessity. In particular:

- `NO_SELECTION_WITNESS` is not a negative musical verdict;
- `SELECTED_NO_FINAL_RECEIPT` is not evidence that the edit survives in final bytes;
- `FINAL_RECEIPT` is not a ProofType or Permit.

No productive consumer is added in r1193.

## Acceptance

The take must pass dependency preflight, Take-Change-Control, formatting, tests, build, strict Clippy and full 10/10 corpus. If it is zero, the r1192 UNKNOWN population has no selected-state receipt witness in the covered handoffs; source evidence can then decide whether those cases are transient/superseded rather than forcing artificial final lineage. If it is non-zero, only that selected subset is a legitimate target for further receipt transport.
